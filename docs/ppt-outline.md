  - 资产：宝可梦、道具、积分

## P4 前端用了什么（35 秒）

- 版式：左侧清单，右侧界面缩略图
- 屏上文字：
  - Vue3 + TypeScript + Vite
  - Pinia 状态管理，Vue Router 路由
  - Phaser3 渲染地图与战斗
  - axios 拦截器统一注入 JWT 与防重放头
  - Web Crypto 做素材校验与随机数复算
- 图：左侧五行，右侧游戏页缩略图，箭头从 Phaser3 指向地图区域
- 备注：表单页面用 Vue，游戏画面用 Phaser 的 canvas，两者嵌在同一页面。选 Phaser 是因为地图要逐帧移动和碰撞检测，DOM 做不了。

## P5 后端用了什么（35 秒）

- 版式：左侧清单，右侧请求链路
- 屏上文字：
  - NestJS 10，按 12 个业务模块拆分
  - TypeORM + PostgreSQL 存账号和日志
  - Redis 存会话、限流、对战房间
  - Socket.IO 推送对战实时状态
  - fabric-gateway 代玩家签名上链
- 图：右侧竖排 `守卫 → 拦截器 → 控制器 → 服务 → ChainAdapter`
- 备注：Nest 的好处是守卫和拦截器把 JWT、权限、防重放、限流统一挂在入口。所有上链操作都收敛在最后一层适配器。

## P6 系统架构（45 秒，核心页）

- 版式：五层堆叠 + 右侧一次请求路径
- 屏上文字：
  - 表现层：浏览器，不直连区块链
  - 应用层：NestJS，所有上链操作在此
  - 身份层：Fabric CA 签发证书
  - 区块链层：2 peer + 1 orderer + 2 CouchDB
  - 支撑层：PostgreSQL / Redis / MinIO
- 图：
  - 左：五层框，应用层与区块链层之间标 `ChainAdapter`
  - 右：`浏览器 → nginx → NestJS → ChainAdapter → peer×2 背书 → orderer 排序 → 写入账本`
- 备注：浏览器只调后端接口。一次写操作要经过反向代理、后端校验、组装交易、两个组织背书、排序，最后才落账本。

## P7 链上存什么，六个合约（55 秒，区块链）

- 版式：左表右合约
- 屏上文字：
  - 链上七类数据：玩家、宝可梦、道具、交易单、对战单、随机事件、幂等记录
  - 不上链：战斗计算、地图、日志、图片
  - 六合约：账户、随机、宝可梦、道具、交易、对战
  - 资产状态机：空闲、交易锁、对战锁
  - 所有变更交易带幂等键，重放返回首次结果
- 图：左侧七行小表；右侧六个合约卡片；底部一行状态机 `IDLE ⇄ LOCKED`
- 备注：判断标准是会不会易主、有没有争议。锁定状态下资产不能转移、不能消耗、不能被第二次交易锁住，双花在状态机层面就被挡住。

## P8 双组织、背书与身份（45 秒，区块链）

- 版式：左右两栏
- 屏上文字：
  - 背书策略 MAJORITY，两组织等于双方都要签
  - 链码升级也要双方批准，单方改不了规则
  - 角色写在证书属性里，链码读证书判权限
  - 仲裁角色强制属于 Org2
  - 争议时资产冻结，只有 Org2 能出终局
- 图：左栏画交易 → 两个 peer → 两个签名；右栏画证书 → role 属性 → 链码校验
- 备注：这是双组织的意义。运营方即使控制了后端，也签不出 Org2 的仲裁签名，裁判因此独立。

## P9 可验证随机数（35 秒，区块链创新点）

- 版式：三步状态机 + 公式 + 局限
- 屏上文字：
  - 链码不能随机：两个 peer 执行结果必须一致
  - 种子在链下生成，链上只存哈希
  - 用时上链重算校验，一个事件只能消费一次
  - rand(n)=HMAC-SHA256(seed, client|event|n)
  - 局限：后端在揭示前能看到种子
- 图：`COMMITTED → REVEALED → CONSUMED` 三格，下方公式，右下角小字"任何人可复算"
- 备注：抽卡和暴击玩家都能自己复算。最后那条局限是我们主动写的，升级方案是接外部随机信标。

# C. 备用页（3 分钟提问用）

## 备用 1 为什么选 Fabric 而不是以太坊

- 屏上文字：
  - 需要指定参与方，不需要匿名共识
  - 有证书准入，角色能写进证书
  - 无 gas，交易不消耗费用
  - 支持多组织背书，正好对应运营方与仲裁方

## 备用 2 共识和出块

- 屏上文字：
  - orderer 单节点 Raft，出块间隔 2 秒
  - 执行在 peer，排序在 orderer，验证在提交时
  - 单 orderer 是课程简化，生产要 3 或 5 节点
  - orderer 挂了账本变只读，peer 挂了写不进

## 备用 3 背书策略与组织数量

- 屏上文字：
  - 当前 2 组织，MAJORITY 等于两个都要签
  - 加同组织 peer 不提高门槛，只加冗余
  - 加组织才提高门槛，要改通道配置
  - 3 组织时 MAJORITY 是 2/3，反而更抗宕机

## 备用 4 为什么战斗不上链

- 屏上文字：
  - 一场战斗上百次掷点，链上吞吐不够
  - Fabric 先执行后排序，出块 2 秒
  - 链上只存结果哈希与服务端签名
  - 回合日志在链下，可按哈希复核

## 备用 5 链上链下冲突与并发

- 屏上文字：
  - 同一键被并发修改，后到的交易验证失败
  - 所以用锁定状态机加幂等键
  - 交易过期可解锁，对战有兜底结算
  - 资产不会被永久卡住

## 备用 6 双链模式与已知限制

- 屏上文字：
  - Mock 模式状态存 Redis，语义复刻链码
  - 真链模式真实背书、排序、提交
  - 限制：私钥托管、单 orderer、种子对后端可见
  - 升级方向：HSM、多节点、外部随机信标

# E. 答辩提问备答

| 问题 | 回答 |
|---|---|
| 前端为什么用 Phaser | 地图要逐帧移动和碰撞检测，DOM 做不了；表单页仍用 Vue |
| 后端为什么用 NestJS | 守卫和拦截器把 JWT、权限、防重放、限流统一挂在入口 |
| 为什么链码也用 TypeScript | 与后端共用哈希和签名实现，避免两边计算结果不一致 |
| 这算联盟链吗 | 机制上算：证书准入、两组织、双方背书、无代币；部署是单机模拟，换机器不用改代码 |
| 两个组织在一台机器上有意义吗 | 证书、容器、状态库隔离，代码强制双方签名，部署位置不影响规则 |
| 仲裁为什么可信 | 仲裁角色强制要求 Org2 证书，控制后端也签不出这个签名 |
| 随机数公平吗 | 不能换种子、不能赖账、可被第三方复算；但后端揭示前能看到种子，写在限制里 |
| 为什么不用区块哈希当随机源 | Fabric 交易在排序前执行，拿不到区块信息；链码也不允许依赖不确定性 |
| 资产会不会永久锁死 | 交易有过期解锁，对战有兜底结算和仲裁退款 |
| 后端挂了怎么办 | 链上状态还在，进行中的对局可走争议由仲裁退款 |
| 和普通数据库比优势在哪 | 资产归属和随机结果不靠运营方自觉，第三方能独立核对 |
| 数据量多大 | 6 个链码合约、5 张 CouchDB 索引、15 张地图、386 个种族 |
